## 1. 必须处理（按优先级）

### 1.1 P0：v617 没有被接进构建，源码也不在本地

```
scripts/build-jbb.sh:15   -o "$OUT" src/jbb_v616.c     ← 仍编译 v616
```

- 现在跑 `pack-deb.sh` 打出来的 deb，**tweak 部分还是旧代码**，A–G 一个都不会生效。
- `src/jbb_v617.c` 只存在于 NAS 副本（`/Volumes/SSD/ios chajian/jbb/src/`），
  本地工作目录 `/Users/dan/Desktop/iphone/jbb/src/` 里没有这个文件。
- 文档 §3 说"把 `pack-deb.sh` 的 VER 改成 6.17.0"——当前实际是 **6.19.0**（设置界面那条线的版本），这句已经过期。

建议：

1. 把 v617 同步进本地仓库；
2. `build-jbb.sh` 改成编译 v617（或加参数选择源文件）；
3. 版本号统一：源码命名 `jbb_v617.c` 保持不变，**deb 版本用 6.20.0**，不要再回 6.17.x（会和 prefs 那条线的 6.17.8 撞车）。

### 1.2 P0：G 的「安全默认」会让全新安装完全不生效

`if (!configFound) { gEnabled = 0; return; }`

全新安装时 `com.pandan.jbb.plist` 不存在 → 三条路径都拿不到配置 → `gEnabled=0` → **jbb 一个 hook 都不装**。
用户装完打开 App 发现"没有任何效果"，只会认为插件坏了。

建议二选一：

- postinst 写一份默认配置（`globalEnabled=true`, `profiles={}`），让"文件不存在"变成"读到默认开"；
- 或者区分两种情况：**文件不存在 = 用默认值（开）**，**文件存在但读不到 = 安全默认（关）**。

### 1.3 P1：G 说「设置经 cfprefsd 写入」是错的

设置端的保存是：

```objc
// JBBPrefsCommon.m:37
[data writeToFile:kJBBPrefsPath atomically:YES];   // 直接写文件，不走 cfprefsd
```

而 tweak 侧 G 项改成**先读 cfprefsd**。cfprefsd 有自己的缓存，直接改文件它不一定立刻看到，
可能出现「设置里明明开了，tweak 读到的还是 nil/旧值」。

建议：

- 设置端保存时**双写**：`CFPreferencesSetAppValue` + `CFPreferencesAppSynchronize`（再加文件写，给宿主/root 用）；
- tweak 侧顺序保持 cfprefsd 优先，文件兜底。

这条必须上 `.20` 实测，不能靠推理。

### 1.4 P1：文档把假设写成了事实（会误导下一个 AI）

- 文档写"open-bugs §4 在 `.20` 真机发现：沙盒 App 读不到配置" —— **没有在 `.20` 验证过**。
  open-bugs §4 明确写的是"最可能的根因（待验证）"，实验在 `.28` 上做了一半就中断了。
- 文档写"用户指示按最新研究安排，故保留默认不生效" —— **用户没有做过这个决定**。
  这属于替用户拍板，必须改成"待确认"。

### 1.5 P2：D 的伪造指针本身是一个特征

真实的 `all_image_info_addr` 指向 dyld 的 `__DATA`。现在改成指向 jbb.dylib 的静态数据段：

- 检测方可以校验"这个地址是否落在某个已加载镜像的 `__DATA` 段内"，不满足就是异常；
- `memcpy(&gFakeInfos, real, sizeof(gFakeInfos))` 按 SDK 结构体大小拷贝，目标系统结构体更小时会读越界（文档已承认）；
- 共享静态缓冲 + 只锁构建不锁读取 → TOCTOU（文档已承认）。

不是不能做，但要意识到这是**新增**的可检测面，而不是纯粹的"补漏"。

### 1.6 P2：F 的偏移不变量必须真机确认

前提是「`ATTR_CMN_RETURNED_ATTRS` 先写、`ATTR_CMN_NAME` 是 bit 0，所以固定落在记录偏移 24」。
这与 XNU 的打包顺序一致，但建议在真机上做一次对照：

- 同一目录分别用 `readdir` 和 `getattrlistbulk` 列一遍，比对条目数；
- 打开 `FSOPT_PACK_INVAL_ATTRS` 再跑一遍，确认不会读错名字（错读的后果是把不该隐藏的项隐藏，或反过来泄漏）。
